# MISSION.md 格式

`MISSION.md` 位于工作区根目录，记录用户**为什么**想搞懂这个主题。所有教学决策（下一课讲什么、举什么例子、设计什么练习）都应溯源到它。

## 模板

```md
# 目标：{主题}

## 为什么想懂
{1-3 句。用户真实世界里想达成的具象结果。懂了之后他生活/工作里什么变了？
避免"为了理解 X"这种抽象说法，往下挖一层的真实诉求。}

## 搞懂之后的样子
- {一个具体、可观察的他能做到的事}
- {另一个具体的事}

## 约束
- {时间、基础、学习偏好、任何限定范围的东西}

## 暂不涉及
- {用户明确现在不想碰的相邻主题，保护最近发展区}
```

## 规则

- **一个工作区一个目标。** 想学两件不相关的事 = 两个工作区。
- **具体胜过抽象。** "能给老妈讲清养老金" 胜过 "了解金融"；"让客户看懂我们的方案" 胜过 "学习产品"。
- **含糊就追问。** 用户说不清为什么，先访谈再写。烂目标比没目标更糟。
- **现实变了就改。** 目标会变，改了同步更新 `MISSION.md` 并写一条 learning-record。
- **保持短。** 超过一屏就不再是指南针，变成计划书了。
