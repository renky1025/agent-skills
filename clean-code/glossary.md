# Clean Code Glossary

术语按字母序排列。格式：`**Term** — 一句话定义 (Ch N)`。

- **Abstract Factory** — 让调用方决定"何时建"、把"怎么建"留在 main 侧的工厂模式，用于隔离构造与多态创建 (Ch 11, Ch 16)
- **Adapter Pattern** — 把自有理想接口翻译为第三方/尚未定义接口的设计模式，桥接双方、集中变更点 (Ch 8)
- **Boy Scout Rule** — 离开模块时比接手更干净，每次 checkin 做微小有益改进以阻止腐坏 (Ch 1, Ch 15)
- **Broken Windows** — 一处破窗诱发更多混乱的隐喻，坏代码会"诱惑"混乱生长 (Ch 1)
- **Build-Operate-Check** — 测试三段式：构建数据、操作数据、校验结果 (Ch 9)
- **Command Query Separation (CQS)** — 函数要么改状态要么答问题，不可兼做，消除动词/形容词歧义 (Ch 3)
- **Cohesion** — 方法操作同一组实例变量的程度，越高越内聚，下降即应拆类 (Ch 10)
- **Cross-Cutting Concern** — 横切多个对象、无法干净隔离的关注点（持久化、事务），用 AOP 表达 (Ch 11)
- **Dependency Inversion Principle (DIP)** — 依赖抽象而非具体细节，构造函数注入，既解耦又易测 (Ch 10, Ch 11)
- **DTO (Data Transfer Object)** — 只有 public 变量、无函数的哑数据类，用于 DB/socket 与领域间翻译 (Ch 6)
- **Encapsulate Conditionals (G28)** — 把 `if (a && !b)` 抽成 `shouldDelete()` 之类意图命名方法 (Ch 17)
- **Explanatory Variables (G19)** — 把多计算挤在一行的表达式拆成带含义的中间变量 (Ch 16, Ch 17)
- **F.I.R.S.T.** — 干净测试五律：Fast、Independent、Repeatable、Self-Validating、Timely (Ch 9)
- **Feature Envy (G14)** — 方法经由别人 accessor 操作别的对象数据，说明它属于那个对象 (Ch 16, Ch 17)
- **Festering Pile** — 每次增量加功能就变丑一点的代码堆 (Ch 14)
- **Flag Argument (F3)** — 用布尔参数选多种行为，宣告"我做了不止一件事"，应拆函数 (Ch 3, Ch 17)
- **God Class** — 暴露约 70 个 public 方法的超大职责类 (Ch 10)
- **Hybrid** — 半对象半数据结构，既有行为又有公开访问器，最难加类型也最难加函数 (Ch 6)
- **Implicity** — 上下文未显式落进代码的程度，越高越难懂（好名字降 implicity） (Ch 2)
- **LeBlanc's law** — "Later equals never"：清理必须就地做，别记到以后 (Ch 1)
- **Learning Tests** — 用受控测试探索第三方 API，升级时即免费回归测试 (Ch 8, Ch 9)
- **Law of Demeter / Shy Code (G36)** — 只与直接协作者通信，避免 `a.getB().getC()` 传递导航 (Ch 6, Ch 17)
- **Magic Number (G25)** — 不自解释的字面量（含字符串），应提成具名常量 (Ch 16, Ch 17)
- **niladic / monadic / dyadic / triadic** — 函数参数个数 0/1/2/3，越少越好，>3 需特别理由 (Ch 3)
- **Noise words** — Info/Data/Variable/Table 等不增加含义的冗余词 (Ch 2)
- **Object vs Data Structure (Anti-Symmetry)** — 对象隐藏数据暴露行为；数据结构暴露数据无行为，两者互补对立 (Ch 6)
- **Open-Closed Principle (OCP)** — 对扩展开放、对修改关闭，靠抽象基类+子类接纳变化 (Ch 10, Ch 12)
- **ONE SWITCH rule (G23)** — 对某类选择全系统至多一个 switch，其 case 须产出多态对象 (Ch 14, Ch 17)
- **POJO** — 纯领域对象，不依赖企业框架，易测试驱动与复用 (Ch 11)
- **Polymorphism over switch (G23)** — 重复出现的 switch/if-else 链改用多态取代 (Ch 16, Ch 17)
- **Single Responsibility Principle (SRP)** — 一个类只有一个变更理由，用 25 词描述不含 if/and/or/but (Ch 10, Ch 13)
- **Special Case Pattern** — 用代表特殊情形的对象替代异常/默认值分支，client 免 if/else (Ch 6, Ch 7)
- **Step-down Rule** — 模块自上而下读如 TO 段落，每函数后接下一层抽象 (Ch 3, Ch 5)
- **Template Method** — 基类固定不变算法骨架，变体步骤留给子类，消除高层重复 (Ch 12)
- **Temporal Coupling (G31)** — 隐藏的先后调用顺序依赖，应显式固化（如合并函数） (Ch 3, Ch 15, Ch 17)
- **Three Laws of TDD** — 先写失败测试、只写足够失败的测试、只写足够通过的生产代码 (Ch 9)
- **Train Wreck** — `ctxt.getOptions().getScratchDir().getPath()` 式耦合调用链 (Ch 6)
- **Try-Catch-Finally First** — 先写 try-catch-finally 界定事务作用域，再填充主逻辑 (Ch 7)
- **Unchecked Exceptions** — 优先 unchecked 异常，避免 checked 异常违反 OCP 的级联改签名 (Ch 7)
- **Walking Skeleton** — 最小耦合的端到端切片，按需生长基础设施，反对 BDUF (Ch 11)
- **Wrapper / Wrap Third-Party** — 包装第三方 API，把多类异常收敛为单一自有异常类型 (Ch 7, Ch 8)
